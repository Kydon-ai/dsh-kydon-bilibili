# npm 0.0.2 包缺少运行文件记录

## 现象

安装 `@kydon/dsh-kydon-bilibili@0.0.2` 时，依赖安装完成后，DSH 在校验 bundle overlay 阶段因找不到插件目录下的 `cordis.yml` 而拒绝安装，并回滚 profile 的 `package.json`、`pnpm-lock.yaml` 和 `node_modules`。

## 原因

`package.json` 的 `dsh.bundle.patch` 指向 `./cordis.yml`，但原来的 `files` 白名单没有包含该文件。`cordis.yml` 在仓库源码中存在且已跟踪，故障发生在发布打包阶段：压缩包没有带上运行时声明要求读取的补丁层。

本地 `pnpm pack --dry-run` 的文件清单不含 `cordis.yml`；从 npm 下载的实际 `0.0.2` 压缩包也不含该文件。因此，DSH 报告的 `ENOENT` 与包内容相符，不是客户端安装目录或 profile 回滚造成的路径问题。

## 额外发现

实际 npm `0.0.2` 压缩包还缺少 `lib/index.js`、`lib/client.js` 和 `lib/types` 文件，而包内 `package.json` 的入口仍指向这些路径。包内依赖版本也保留了 `workspace:^`。这些内容与本地 `pnpm pack` 产生的包不同，说明发布到 npm 的 `0.0.2` 产物不完整；补入 `cordis.yml` 并不能单独证明该版本的其他运行文件齐全。

## 修复

本地 `package.json` 的 `files` 白名单已加入 `cordis.yml`。这项源码修改不会改变已经发布的 `0.0.2` 压缩包；该版本在 npm 上仍缺少所需文件。重新发布时需要提升版本，并确保打包前已生成 `lib` 构建产物。

## 验收记录

| 检查 | 结果 |
|---|---|
| `package.json` 补丁声明 | `dsh.bundle.patch` 指向 `./cordis.yml` |
| 原始本地打包清单 | 未包含 `cordis.yml` |
| npm `0.0.2` 文件清单 | 未包含 `cordis.yml`、`lib/index.js`、`lib/client.js` 或 `lib/types` |
| npm `0.0.2` 包内依赖声明 | 仍包含 `workspace:^` |
| 当前源码白名单 | 已加入 `cordis.yml`；本次记录前尚未重新打包验证 |

下次发布前，应从最终 tarball 确认 `cordis.yml`、Host/Client 构建产物和类型文件均存在，并确认包内依赖版本已由 workspace 协议转换成可从 registry 安装的版本范围。
